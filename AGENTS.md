# ActiveBook — инструкции для ИИ-агентов

Репозитории располагаются рядом. Перед работой **обязательно прочитайте**:

1. [Общие соглашения по разработке](./CODING_CONVENTIONS.md) — стандарты кода, React/JSX, CSS, структуры каталогов и тестов.
2. Локальный `AGENTS.md` целевого репозитория — команды, границы системы и особые инструкции.

В других репозиториях общие правила доступны по пути `../active-book-common/CODING_CONVENTIONS.md`. При противоречиях уточняйте предметные ограничения локальной реализации и не отменяйте общие договорённости молча.

## Работа над задачами

- Перед изменением изучите существующую реализацию и её использование. Не выполняйте несвязанные с задачей массовые рефакторинги.
- После изменения выполняйте применимые проверки типов, линтеры и тесты. Не утверждайте, что проверки прошли, если они не выполнялись; сообщайте точные блокеры.
- Даже если в целевом репозитории отсутствуют ESLint, Stylelint или их локальные конфигурации, соблюдайте правила из `active-book-common/configs/linters/eslint.js` и `active-book-common/configs/linters/stylelint.js`. Ознакомьтесь с ними до написания кода и применяйте подходящие правила к TS/JS/JSX и CSS/SCSS; отсутствие линтера не разрешает произвольное форматирование.
- Не добавляйте линтеры в репозиторий только ради этого требования. Если соответствующая проверка недоступна, сообщите об этом вместо заявления о её успешном выполнении.
- Не добавляйте зависимости и собственные инфраструктурные решения без реальной необходимости.
- Клонируйте нужные репозитории рядом и устанавливайте common до потребителей. Пользуйтесь штатными импортами и наследуемыми конфигурациями.

## Коммиты и публикация изменений

- Если задача подразумевает изменение исходников, документации или конфигурации и пользователь не указал обратного, после реализации и проверок **создайте коммит и выполните push** в текущую рабочую ветку. Не оставляйте готовые изменения только локально.
- Если задача ограничена анализом, ревью или обсуждением без изменения файлов, коммит и push не требуются.
- Не выполняйте merge, rebase с переписыванием истории, force push, публикацию релиза или push в `main` без явного разрешения.
- При ошибках или невозможности запуска проверок сообщите об этом явно.
- В финальном отчёте укажите репозиторий, ветку, хеш коммита, результат push и состояние рабочего дерева.

## Особенности active-book-common

Приватный ESM-пакет `@active-book/common` на Node.js 24 LTS (24.15+ в ветке 24.x) и npm 11.x. Не создавайте workspaces.
Скрипты используют стандартные API Node и npm CLI без shell-команд.
Запускайте `npm run test:infra` для скриптов common.
`npm run check` проверяет группы соседних репозиториев, включая браузер; подгруппы выбираются явно.
`deps:sync` использует стандартные npm install и только секции dependencies/devDependencies
внутри ActiveBook. Не нужны собственный поиск npm, semver-парсер, snapshots и rollback.

`deps:sync` синхронизирует только версии в ожидаемых секциях. Категории никогда не переносит;
peerDependencies и optionalDependencies игнорирует. Ошибки управляемых категорий
собирает и продолжает корректные обновления. Тестовые repos не регистрируйте.
